Metric Tree Construction

Breaking a metric into its constituent drivers for systematic diagnosis

Revenue is down 8% and three people in the room have three different theories. Without a shared structure, you'll spend 45 minutes debating opinions. A metric tree ends the debate with a clean identity: revenue = users × sessions-per-user × orders-per-session (conversion) × AOV — each term per-unit, so the factors actually multiply back to revenue. The tree tells you which node or nodes to investigate first; a drop can live in more than one (a single deploy can dent both conversion and AOV at once). Build it before you theorize, not after.

How this connects to experimentation: In A/B test analysis, the metric tree tells you which sub-metric drove the primary metric movement — and whether that's the one you intended to move. Metric trees make post-experiment attribution as structured as pre-experiment design.

Key takeaways

  • Build the identity before theorizing: revenue = users × sessions/user × conversion × AOV, each term per-unit so the factors multiply back.
  • The tree tells you which node(s) to investigate first — a drop can live in more than one.
  • Build the tree before the debate, not after it.
